# 2026-07-30 Linux Intel demo 加速优化证据

本目录记录 Issue #44 在物理 Linux Intel 主机 `iWORK` 上完成的 CSC3 demo
优化、验证和独立进程实验。本轮只修改组装实现和回归测试，没有修改计时定义，
没有画图，也没有修改绘图脚本。

## 结论

- 源码提交：`7da2897ab1b01a4aa028dc91a2885d0232fad01d`。
- 算例：`3d-WindTurbineHub.inp`，1,113,684 个 Tet4、685,152 个自由度、
  14,093,676 个 CSC3 非零元。
- 完整线程范围：$p=1,2,\ldots,20$。
- 每个线程数独立启动进程，预热 $W=2$，正式重复 $R=7$，全部样本串行执行。
- 140 个正式样本和 40 个预热样本全部退出码为 0，正确性为 `PASS`，实际线程数
  与请求值一致。
- 独立串行基准中位数为 3,527.288 ms。
- 最佳点为 $p=19$：完整调用中位数 848.731 ms，加速比 4.155953。
- $p=20$：符号阶段 748.657 ms，数值阶段 107.954 ms，完整调用 855.506 ms，
  加速比 4.123042。

这里的完整调用时间始终是
$t_{\mathrm{total}}=t_{\mathrm{symbolic}}+t_{\mathrm{numeric}}$。输入检查、
结构生成、scatter 生成、数值检查、整体矩阵清零和 atomic 累加都保留在各自
调用的总耗时内。

## 原因

旧实现不是 atomic 累加本身只能达到 2 倍，而是每次完整调用还做了几项很大的
单线程重复工作：

1. WindHub 的 1,113,684 个单元编号本来已经有序，demo 仍然建立索引并完整排序。
2. 为检查自由度编号，demo 复制并排序全部自由度引用；检查每个 Tet4 时还反复
   创建很小的临时数组。
3. 每次数值组装都串行重扫 86,867,352 个 scatter 目标，尽管这些目标已经在
   符号阶段生成并逐项验证。
4. 约 1.60 亿个局部矩阵值的有限性和对称性检查以及整体矩阵清零都串行执行。

本轮优化给已排序输入增加直接路径，用标记表检查紧凑自由度编号，消除 Tet4
检查中的小数组分配；数值阶段复用同一个 OpenMP 线程组并行完成矩阵值检查、
清零和 atomic 累加。scatter 目标仍在符号阶段逐项验证，提交后通过只读接口
使用，不再在每次数值组装时串行做同一遍检查。

## 与旧实验对比

| 指标 | 2026-07-29 旧实现 | 2026-07-30 新实现 |
|---|---:|---:|
| 独立串行基准中位数 | 3,634.677 ms | 3,527.288 ms |
| 最佳线程数 | 18 | 19 |
| 最佳完整调用中位数 | 1,494.753 ms | 848.731 ms |
| 最佳加速比 | 2.431624 | 4.155953 |
| $p=20$ 符号阶段中位数 | 1,282.419 ms | 748.657 ms |
| $p=20$ 数值阶段中位数 | 248.852 ms | 107.954 ms |
| $p=20$ 完整调用中位数 | 1,524.917 ms | 855.506 ms |
| $p=20$ 加速比 | 2.383525 | 4.123042 |

新实现的 $p=20$ 完整调用比旧实现缩短约 43.9%。峰值常驻内存按每个独立
子进程采集，$p=20$ 中位数约为 4.783 GiB；没有把多个算法放进一个进程后共用
同一条峰值记录。
