# CSC3 对称稀疏组装 Demo Windows 内部评估

> 仅供内部评估

## 结论

**PASS。** Issue #54 要求的 Windows x64 双工具链构建、CTest、外部 consumer、clean-room 构建、完整线程扫描、矩阵正确性与交付包校验均已获得可追溯的实际证据。

## 评估摘要

- MSVC + Ninja 与 MinGW-w64 + Ninja 均在 Windows 上完成配置、编译、CTest 和外部 consumer 验证；两套工具链的 OpenMP 缺失门禁也按预期拒绝配置。
- 同一份确定性源码 ZIP 已分别在两个新目录中完成 MSVC 与 MinGW clean-room 构建，未借用原仓库的构建目录或缓存。
- WindHub 性能实验覆盖 $p=1,\ldots,16$，每档预热 $W=2$ 次、正式测量 $R=7$ 次，共 144 个串行样本；每个样本均由新启动的子进程执行。
- 最大相对 Frobenius 误差为 $1.510488\times10^{-16}$，满足 $10^{-8}$ 验收阈值。
- 最优总体加速比出现在 $p=16$，为 $2.1490$；对应并行总时间中位数为 $1428.320\ \mathrm{ms}$。$p=1$ 时并行路径慢于串行基线，说明固定开销真实存在，报告未隐藏该结果。
- 峰值内存占用来自 Windows `GetProcessMemoryInfo().PeakWorkingSetSize` 实测，各线程档位中位数约为 $4.797\ \mathrm{GiB}$；该数值与代码中的持久容量估计分开报告。

## 适用边界与风险

- 结论只适用于本次 Windows 主机、当前 WindHub 输入和报告所列工具链版本，不外推到其他模型、硬件或操作系统。
- 线程数从 8 增加到 16 后仍有改善，但收益已明显趋缓；当前结果证明实现可并行且可交付，不代表理想线性扩展。
- 性能原始数据对应提交 `14d89fad3b643b0ce81047aecbddd3e1cfb504e2`；交付源码 ZIP 对应提交 `419221b0ce58e37fca41fe48bbcbca9f71709ecf`。两者之间仅修正了交付打包器测试对原仓库 `.git` 目录的隐式依赖、包内报告链接和版本追溯字段，没有改动算法、公开接口或基准程序。
- 交付源码 ZIP 不包含 WindHub 的 Git LFS 大文件实体；复现实验时必须另行取得与报告 SHA-256 一致的输入文件。CTest、consumer 和 clean-room 构建不依赖该实体。
