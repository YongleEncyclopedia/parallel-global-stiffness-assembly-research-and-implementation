# CSC3 两阶段并行组装算法

这份 Demo 解决的是有限元整体刚度矩阵组装问题。各单元先得到自己的单元刚度矩阵，随后把这些矩阵中对应同一全局自由度的条目累加到整体矩阵中。

实现分为两个阶段：

1. `Symbolic()` 根据网格拓扑和自由度编号建立 CSC3 稀疏结构，同时算好每个局部条目的写入位置；
2. 并行遍历单元，通过 `add()` 把单元刚度矩阵原子累加到 CSC3 的 `values` 中。

两个阶段之间由 `HelpInfo::scatter` 衔接。

```text
DofCodingInfo
    │
    └── Symbolic() ──> Csc3Matrix 的结构 + HelpInfo
                                      │
                       zero_values() ─┤
                                      │
                 OpenMP 并行调用 add()
                                      │
                                      └──> Csc3Matrix::values
```

## 1. 输入和输出

公开类型都声明在 [`include/csc3_demo/assembly_helper.h`](include/csc3_demo/assembly_helper.h) 中。

| 类型 | 作用 |
|---|---|
| `DofCodingInfo` | 保存“单元到节点”和“节点到全局自由度”的映射。 |
| `Csc3Matrix` | 保存对称整体矩阵的上三角，包括列偏移、行号和数值。 |
| `HelpInfo` | 保存按单元展开的自由度以及局部条目到 CSC3 的散射位置。 |
| `ElementStiffness` | 描述一个完整、对称、行主序的单元刚度矩阵。 |
| `AssemblyHelper` | 提供 `Symbolic()`、`zero_values()` 和 `add()`。 |

矩阵和数组下标使用零基。节点编号与单元编号必须非负，但可以不连续；全局自由度必须连续编号为

\[
0,1,\ldots,n-1.
\]

### CSC3 在本项目中的含义

`Csc3Matrix` 按列保存对称矩阵的上三角。第 $j$ 列的条目位于

\[
[\mathtt{col\_ptr}[j],\mathtt{col\_ptr}[j+1])
\]

这段区间内，`row_idx` 严格递增，并且行号 $i$ 满足 $i\le j$。`values` 与 `row_idx` 等长，两者相同下标对应同一个矩阵条目。

当一对全局自由度为 $a$ 和 $b$ 时，存入 CSC3 的位置统一写成

\[
i=\min(a,b),\qquad j=\max(a,b).
\]

因此不论局部矩阵中的两个自由度原来是什么顺序，最后都只会落到整体矩阵的上三角。

## 2. 两阶段组装

直接组装时，每处理一个局部条目都要在稀疏矩阵中查找它的全局位置。有限元分析往往会在同样的网格拓扑上反复组装矩阵；如果网格拓扑和自由度编号没有变化，这些查找每次得到的结果也不会变化。

本 Demo 把这部分工作提前到 `Symbolic()` 中。符号阶段只处理“哪些位置存在”，不读取刚度数值；数值阶段只沿着已经生成的 `scatter` 写入。

这样做主要有两个好处：

- CSC3 的结构只需建立一次；
- 后续每轮数值组装不再对 `row_idx` 做搜索。

## 3. 并行符号组装

`Symbolic(csc3, help_info, dof_coding_info)` 最终生成两部分结果：

- `csc3.col_ptr`、`csc3.row_idx` 和已清零的 `csc3.values`；
- `help_info.element_dofs`、各类 offset 以及 `help_info.scatter`。

符号组装中既有串行准备，也有 OpenMP 并行循环。下面按代码的实际执行顺序说明。

### 3.1 整理并检查输入（串行）

`DofCodingInfo` 使用 `unordered_map` 保存数据，容器的遍历顺序不固定。实现先按单元编号排序，再把每个单元的自由度展开为连续数组。这样后面的并行循环不会受哈希表遍历顺序影响。

这一段同时检查：

- 单元、节点和自由度编号不能为负数；
- 单元不能重复引用同一节点或同一自由度；
- 单元引用的节点必须存在；
- 同一个全局自由度不能分配给多个节点；
- 全局自由度必须使用 $0$ 到 $n-1$ 的连续编号。

检查完成后，`element_ids` 按升序排列，`element_dof_offsets` 用来划分每个单元在 `element_dofs` 中的区间。

### 3.2 建立“自由度到单元”的邻接表（串行）

构造 CSC3 的某一列时，需要先知道哪些单元包含该列对应的自由度。实现采用两遍计数法建立压缩邻接表：

1. 第一遍统计每个全局自由度关联了多少个单元；
2. 对计数做前缀和，得到每个自由度在邻接数组中的区间；
3. 第二遍按单元顺序填入单元序号。

若第 $e$ 个单元有 $d_e$ 个局部自由度，邻接数组的总长度为

\[
M=\sum_e d_e.
\]

### 3.3 按列生成稀疏模式（并行）

OpenMP 把 CSC3 的列分给不同线程，每次循环迭代只修改一列。对第 $j$ 列，线程执行以下操作：

1. 找到所有包含自由度 $j$ 的单元；
2. 收集这些单元中不大于 $j$ 的自由度，作为该列的候选行号；
3. 对候选行号排序并去重。

这里按列划分所有权，所以不同线程不会同时修改同一个列容器。排序和去重也使 `row_idx` 不依赖线程调度顺序。

各列长度确定后，程序串行计算 `col_ptr` 的前缀和。此时每列在最终数组中的区间已经固定，再由一个 OpenMP 循环把各列行号复制到互不重叠的 `row_idx` 区间。

### 3.4 建立散射表（并行）

局部自由度数为 $d_e$ 的对称单元矩阵，在整体矩阵中需要写入的上三角条目数为

\[
s_e=\frac{d_e(d_e+1)}{2}.
\]

程序先计算每个单元在 `scatter` 中的起止位置，再用 OpenMP 按单元并行填表。每个局部上三角条目都执行一次以下操作：

1. 把两个局部自由度换成全局自由度；
2. 用较小编号作为行、较大编号作为列；
3. 在目标 CSC3 列中二分查找行号；
4. 把对应的 `values` 下标写入 `scatter`。

例如，一个单元只有两个自由度 `[2, 5]`。局部上三角按行主序依次为

\[
(0,0),\ (0,1),\ (1,1),
\]

对应的全局条目是

\[
(2,2),\ (2,5),\ (5,5).
\]

`scatter` 保存这三个条目在 `csc3.values` 中的下标。数值阶段仍按相同顺序遍历局部上三角，因此可以直接取出目标位置。

### 3.5 写回结果

符号阶段先在临时对象中构造矩阵和散射表。只有输入检查、内存分配、列构造和散射查找全部成功后，才替换传入的 `csc3` 与 `help_info`。

## 4. 并行原子累加数值组装

数值阶段的调用方式如下：

```cpp
csc3_demo::AssemblyHelper helper;
csc3_demo::Csc3Matrix csc3;
csc3_demo::HelpInfo help_info;

helper.Symbolic(csc3, help_info, dof_coding_info);

// 每轮完整组装只清零一次，并且清零不能与 add() 同时进行。
helper.zero_values(csc3);

#pragma omp parallel for schedule(static)
for (std::int64_t e = 0; e < element_count; ++e) {
    const auto elem_id = help_info.element_ids[static_cast<std::size_t>(e)];
    const auto& ke = element_stiffness.at(elem_id);
    helper.add(csc3, help_info,
               csc3_demo::ElementStiffness{elem_id, ke.data(), ke.size()});
}
```

`add()` 自己不创建并行区，它本身不会启动线程；外部的 OpenMP 循环负责把不同单元分给多个线程。

每次 `add()` 处理一个单元：

1. 在已排序的 `element_ids` 中找到单元序号；
2. 通过 offset 取得该单元的自由度区间和 `scatter` 区间；
3. 检查单元刚度矩阵尺寸、有限性和对称性；
4. 检查本单元的全部散射下标；
5. 按行主序遍历局部上三角，并把条目累加到 `csc3.values[scatter[k]]`。

单元刚度矩阵必须传入完整的 $d_e\times d_e$ 行主序数组。实现会检查上下三角是否对称，但实际写入时只读取上三角。

### 为什么使用 atomic

相邻单元会共享节点和自由度，因此两个线程可能同时更新整体矩阵中的同一条目。普通的

```cpp
csc3.values[target] += value;
```

包含“读旧值、相加、写回”三个动作。线程交错时，其中一次更新可能覆盖另一次更新。实现对最终写入使用

```cpp
#pragma omp atomic
csc3.values[target] += value;
```

保证每个单元贡献都被保留。原子操作只包住共享数值的加法；单元定位、输入检查和散射下标读取仍在线程自己的执行路径中完成。

求解器代码需要保证每个单元恰好调用一次 `add()`。漏掉单元会少装，重复调用会重复累加。传入并行区的数据也应在进入循环前准备正确，避免 C++ 异常越过 OpenMP 并行区边界。

## 5. 正确性和误差

符号组装阶段按单元编号整理输入，按列独占写入，并在每列内排序去重。因此同一份输入使用不同线程数时，`col_ptr`、`row_idx` 和 `scatter` 应逐项一致。

数值组装阶段的情况不同。浮点加法不满足结合律，不同线程到达同一原子条目的先后顺序可能不同，所以并行结果允许出现舍入量级的差异。测试不要求数值逐位相同，而是把并行结果与独立串行参考实现比较。

串行参考实现位于 [`tools/src/validation.cpp`](tools/src/validation.cpp)。它从原始拓扑重新建立参考矩阵，不复用 `HelpInfo` 或候选实现的散射逻辑，避免两条路径共享同一个错误。

## 6. 符号组装结果的复用条件

只要下面两项没有变化，`Csc3Matrix` 的结构和 `HelpInfo` 就可以复用：

- 单元与节点的连接关系；
- 节点到全局自由度的编号关系。

下一轮数值组装只需先调用 `zero_values()`，再并行处理全部单元。材料参数、单元刚度数值或载荷步发生变化，并不要求重新运行 `Symbolic()`。

如果网格拓扑、自由度数量或自由度编号发生变化，就必须重新执行符号组装。

## 7. 工作量和适用范围

令单元总数为 $E$，全局自由度数为 $n$，第 $e$ 个单元的局部自由度数为 $d_e$。`HelpInfo::scatter` 的长度为

\[
S=\sum_e\frac{d_e(d_e+1)}{2}.
\]

每轮数值组装进行 $S$ 次原子累加。符号阶段的主要工作是收集并排序各列候选行号，以及为这 $S$ 个局部上三角条目查找 CSC3 位置。符号结果可以复用时，这些搜索不会进入后续数值组装。

atomic 方法实现直接，额外内存较少，但共享条目较多时会出现原子竞争。实际加速效果取决于网格连接关系、线程数、处理器和内存系统。
